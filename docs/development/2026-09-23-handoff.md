# Serve corpus and analysis quality handoff

> **Status:** Current · **State:** Maintained · **Work:** Next · **As of:** 2026-09-23

## Current state

Serve Review runs locally on macOS and WSL2. `mise run process -- TARGET` finds
serve attempts, cuts source video, and analyzes detected attempts with
MediaPipe pose, ball/racket/audio evidence, stage checkpoints, and fingerprints.
The current quality project is to measure and improve serve detection and the
three most useful visual checkpoints: release, cocking, and contact. The broader
biomechanics and injury-prevention claims still need separate scientific review
and measurement validation; current pose-derived values are not clinical advice.

The local review site (`mise run annotate -- SESSION_DIR`) lets the sole user
classify each detected attempt, scan complete videos for misses, and correct
those three checkpoints on confirmed serves. It stores source-bound human labels
in ignored `annotations/review-annotations-v1.json`; generated predictions stay
in `metadata/` and may be regenerated. Other five checkpoint labels already
saved remain intact, but do not count toward focused review progress.

As of this handoff, the ignored `corpus/2026-09-08/` pilot has 11 rear-view
videos, all marked fully scanned. Its labels include 39 serves (15 added as
detector misses), 4 shadow swings, 2 toss/aborts, and 1 other. All 117 focused
checkpoint slots on those serves have a saved review status. These are review
coverage counts, not precision/recall or checkpoint-error estimates. The
annotations are private local data and are not part of the commits.

Google Photos exports can bake slow motion and speed ramps into one video. The
source PTS and all annotation times follow playback, not original capture
time. Event order and visual timestamps can be evaluated on that timeline;
durations, velocities, and accelerations cannot be interpreted as physical-time
measurements without original captures or a recovered time map.

## Performance status

In the pilot, the cut/detection stage dominated elapsed time, especially CPU
pose inference. `mise run process -- SESSION_DIR --cut-workers 2` now permits
two independent video cuts concurrently on a CPU-rich WSL machine. The default
is still one worker for both machines; per-serve GPU analysis remains serial.
An uncached end-to-end wall-time comparison has not yet been measured.

On the WSL2 RTX 5070, the Python MediaPipe Tasks GPU delegate initialized with
Mesa llvmpipe, a CPU software renderer, so it was not adopted. Google's
[framework CUDA instructions](https://developers.google.com/edge/mediapipe/framework/getting_started/gpu_support#tensorflow_cuda_support_and_setup_on_linux_desktop)
describe a TensorFlow/Bazel inference path, not a switch on this repository's
Python `PoseLandmarker` call. Explore hardware-backed graphics inference or a
new CUDA pose backend only if measured bottlenecks justify the integration work.

## Next steps

1. Add independent recording sessions with varied camera views and real/shadow
   examples. Assign roughly 20% of **sessions** to holdout before changing
   heuristics; do not split individual serves from one session across sets.
2. Export the reviewed labels to a small, reproducible detection evaluation:
   one-to-one matching of detected versus labeled serve ranges, precision,
   recall, false positives by class, and missed serves. Keep holdout labels
   sealed during tuning.
3. Evaluate release, cocking, and contact on confirmed serves. Report proposal
   availability and signed/absolute timing error on the playback timeline,
   stratified by view and source type. Do not convert these into physical-time
   error for speed-ramped exports.
4. Use the error cases to make one targeted heuristic change at a time. Check
   review burden as new sessions arrive; hand-labeling every checkpoint may not
   scale, so prioritize uncertain or high-impact examples once an evaluator
   exists.
5. Benchmark an uncached multi-video session with one versus two cut workers,
   recording wall time and CPU/GPU use before changing the default.
