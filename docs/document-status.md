# Document status

> **Status:** Current · **State:** Maintained · **Work:** None · **As of:** 2026-09-14

Every maintained Markdown document under `docs/` begins with a status line using independent lifecycle, maturity, and work-priority fields.

## Status

- **Current:** Describes the repository, product, or process as it exists on the stated date.
- **Proposed:** Describes behavior or work that is not yet current.
- **Historical:** Retained as a record and not authoritative for current work.

## State

- **Placeholder:** Topic exists but substantive documentation has not been written.
- **Draft:** Content is being formed and has not been accepted.
- **In review:** Ready for an explicit decision or review.
- **Accepted:** Approved direction that is not necessarily implemented yet.
- **Maintained:** Current and expected to stay synchronized with implementation or practice.
- **Legacy:** Still applicable to a compatibility path but no longer preferred; the document should identify its replacement or required migration.
- **Complete:** Historical work or record that reached its intended conclusion.
- **Superseded:** Replaced by another document or direction.
- **Deferred:** Valid proposal intentionally postponed.
- **Rejected:** Closed proposal; the document must state the reason, such as infeasible, low priority, or incompatible.

## Work

- **Active:** Work is happening now.
- **Next:** Intended to begin after the active work.
- **Backlog:** Candidate future work with no immediate commitment.
- **Deferred:** Intentionally postponed despite having been considered.
- **None:** Reference or historical material with no planned document work.

`Status` answers whether a document describes reality, a possible future, or history. `State` answers how mature or disposed the document is. `Work` answers whether it is part of the current work queue. The date prevents an old classification from appearing timeless.
